# The demo

The whole product on one small EC2 instance in the AWS sandbox (decision D70), for showing it to prospects before the company's own accounts exist. It is not staging: staging and production are the cell of decision D67, in the company's AWS Organization.

| Piece | Where |
|---|---|
| Instance | `t4g.small` (2 GB, ARM) with 2 GB of swap and a 30 GB disk, Amazon Linux 2023, in Mumbai |
| Processes | Docker Compose ([compose.yaml](compose.yaml)): PostgreSQL 18 with PostGIS and pg_partman, Redis, the API, worker and scheduler, and Caddy |
| HTTPS | Caddy, with a Let's Encrypt certificate for `app.thelamp.in`; it serves the web portal and passes `/v1` and `/auth` to the API, so the portal and the API share one origin |
| Photos | A private S3 bucket, read and written through presigned links |
| Settings | One SSM SecureString (`/thelamp-demo/env`), generated by Terraform, copied to the box at each deploy |
| Sign-in | Demo numbers with fixed codes (`DEMO_CODES`) in demo tenants; the cell sends no codes (`OTP_PROVIDER=none`), and SMS and email go to its log with numbers masked |
| Images | Built on your Mac for ARM and pushed to the sandbox's ECR, tagged with the commit |

It runs on the Free plan's credit: roughly $15–20 a month running (instance, disk, address), and a few dollars paused, when only the disk and the address cost anything. Keep the sandbox's budget alerts on.

## The first time

From the repository root, with Docker running:

1. Sign the CLI in as `kunal-admin`: `aws configure set region ap-south-1 --profile thelamp-sandbox`, then `aws login --profile thelamp-sandbox`.
2. Copy `infra/environments/demo/terraform.tfvars.example` to `terraform.tfvars` beside it, and choose the demo numbers and their codes.
3. `infra/scripts/demo.sh apply` creates the instance, its address, the bucket, the registry and the settings. Note the `address` it prints.
4. At the registrar of thelamp.in, add an `A` record for `app.thelamp.in` with that address. Caddy asks Let's Encrypt for the certificate once the record resolves.
5. `infra/scripts/demo.sh deploy` builds this commit's images, pushes them, and bootstraps, migrates and starts the demo. It needs a clean working tree.
6. Make a demo tenant whose admin is a demo number:

   ```bash
   infra/scripts/demo.sh provision --name "Demo Agro" --slug demo-agro --template agri --status active --admin-name "Demo Admin" --admin-phone +919800000001
   ```

   For a pharma or FMCG prospect, use `--template pharma` or `--template fmcg` (for example `--name "Demo Pharma" --slug demo-pharma`); each demo tenant gets its own content in its industry's words (decision D97). A number belongs to one organisation (decision D103), so each demo tenant needs its own admin number, and the content puts demo numbers only in the first demo tenant to take them; a later one gets fictional people in their slots.

   A prospect's own branding goes in at the same time: `--logo <file on this machine>` (PNG, JPEG or WebP) and `--brand-colour '#486A38'`, checked as Settings checks them.

7. Fill it with a few weeks of fictional work, so every screen has something to show (about half an hour on the instance):

   ```bash
   infra/scripts/demo.sh content --tenant demo-agro --days 26
   ```

8. Sign in at https://app.thelamp.in with that number and its code. For the phone, a preview build with `EXPO_PUBLIC_DIRECTORY_URL=https://app.thelamp.in`.

## Every day

- `infra/scripts/demo.sh deploy` after merging, to show the newest build.
- `infra/scripts/demo.sh pause` after a demo; `resume` before the next one (about two minutes).
- `infra/scripts/demo.sh status` says whether it runs and answers.
- For a fresh story, provision another demo tenant and run `content` on it; a tenant is filled once.

## The content

`pnpm --filter @thelamp/api demo:content --tenant <slug>` (locally) or `demo.sh content` (on the instance) fills a demo tenant that has only its admin. It reads the tenant's own configuration, so it works for any template, and makes:

- territories down to markets around Nashik (real towns), and a team: a manager at each manager level above the lowest, one under the other, two group managers of the lowest and eight field people, the demo numbers among them (the second number a group manager, the third one of his field people); the rest are fictional and never sign in;
- the accounts of each market, with codes, locations, slots and the fields their types require: suppliers, the businesses they supply and people such as farmers or doctors, named in the words of the tenant's industry (agri, pharma or FMCG, decision D97); a few fictional products when a form offers the catalogue or lists items;
- each month's targets, set and locked by the managers;
- every working day (Sundays off, a few absences): the managers' plans, punch-in, a trail of points, planned visits to the accounts each person holds with an order now and then and a form with photos (item lines, dates within the field's limits, and a signature where the form needs one), activities without an account such as farmer meetings or CMEs, now and then a new account proposed for the manager to decide, punch-out, and the managers' reviews, except the last two days', which wait; today stops at the present, so people are on duty;
- what the nightly jobs would do: missed plans and everyone's attendance.

It runs the app's own services as each person, on a simulated clock set to each moment, so every rule applies and the events work out attendance, metrics and leaderboards. At the end it releases the fictional phones of the demo numbers, so real phones can sign in with them.

## Moving to try.thelamp.in

Production's portal needs `app.thelamp.in`, so the demo moves before launch, to `try.thelamp.in` (decision D105; the name may still change):

1. Set `domain = "try.thelamp.in"` in `terraform.tfvars`, then `demo.sh apply` and `demo.sh deploy`. Caddy asks for the new name's certificate once its record resolves.
2. Add the `A` record for `try.thelamp.in` with the demo's address at the registrar, and remove the one for `app.thelamp.in` once nothing uses it.
3. The provisioner wrote the cell's address once, with the first demo tenant, so sign-in would keep handing out the old one: on the box, set `directory.cells.api_base_url` to `https://try.thelamp.in` for the cell `demo`.
4. Make a phone preview build with `EXPO_PUBLIC_DIRECTORY_URL=https://try.thelamp.in`; builds pointed at `app.thelamp.in` stop working once production takes the name.

Changing `terraform.tfvars` (new demo numbers) needs `apply`, then `deploy`, which copies the settings to the box. The state lives in `infra/environments/demo` on the machine that applied it, as it holds the generated passwords; don't lose it, and never commit it.
